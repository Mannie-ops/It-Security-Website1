MIDTERM RESEARCH PROJECT

Machine Learning for Network Intrusion Detection

Investigating whether machine-learning models can distinguish benign network traffic from malicious traffic using a labeled intrusion-detection dataset.

THE SECURITY PROBLEM

Why intrusion detection matters

Network intrusion detection aims to identify traffic patterns associated with suspicious or malicious activity. Detecting attacks can help security teams investigate threats, while false alarms and missed attacks can both affect security operations.

Research question

Can machine-learning models distinguish benign network traffic from malicious traffic, and how do their false-positive and false-negative rates compare?

Supporting research questions

  1. How well can Random Forest and Decision Tree classify the selected benign and brute-force traffic records?
  2. Which model provides the stronger balance of precision and recall on the test data?
  3. What do the confusion matrices reveal about false positives and missed attacks?
  4. Which traffic features appear useful for distinguishing the selected classes?
  5. How might using a sampled dataset and only selected attack types limit how well the findings generalize?

DATASET

CIC-IDS2017

The experiment uses a sampled portion of CIC-IDS2017, including benign traffic and traffic labeled FTP-Patator or SSH-Patator from the selected files.

RESEARCH PLAN

Goals and method

  • Explore and clean labeled network-flow data.
  • Split records into training and test sets.
  • Train and compare two classifiers.
  • Evaluate accuracy, precision, recall, F1-score, and confusion matrices.
  • Use feature importance to help interpret Random Forest predictions.

ASSIGNMENT 7 • CYBERSECURITY RESEARCH

DoS/DDoS Detection & Website Availability

This research investigates whether data-driven methods can recognize denial-of-service traffic and help defenders protect website availability. The analysis uses labeled public network-flow data; no attacks are launched against real systems.

RESEARCH PROBLEM

When traffic overwhelms a website

A Denial-of-Service (DoS) attack attempts to make a service unavailable by overwhelming or exhausting a target's resources. A Distributed Denial-of-Service (DDoS) attack uses many sources or compromised devices to generate attack traffic, making the traffic harder to distinguish and block at a single point.

Research question

Can data-driven methods help detect abnormal network traffic associated with DoS/DDoS attacks in the CIC-IDS2017 dataset?

Objectives

  • Compare normal network flows with labeled DoS and DDoS flows.
  • Explore flow duration, packet rates, byte rates, packet counts, and TCP flag patterns.
  • Train a supervised classifier to distinguish benign traffic from DoS/DDoS traffic.
  • Evaluate detection using precision, recall, F1-score, and a confusion matrix.
  • Explain how early detection and defensive response can support website availability.

DATASET

CIC-IDS2017

Created by the Canadian Institute for Cybersecurity at the University of New Brunswick. It contains labeled network flows, benign activity, and several attack categories captured across five days.

Official CIC-IDS2017 dataset ↗

CIC-IDS2017 on Hugging Face ↗

Relevant labels: BENIGN, DoS Hulk, DoS GoldenEye, DoS slowloris, DoS Slowhttptest, and DDoS.

METHOD

Analysis workflow

  1. Load the labeled CSV flow records.
  2. Normalize labels and remove duplicate, invalid, infinite, and missing values.
  3. Keep BENIGN and DoS/DDoS classes for the focused experiment.
  4. Use a stratified train/test split and train a Random Forest classifier.
  5. Report class-level metrics and a confusion matrix.

NORMAL TRAFFIC

Expected behavior

Normal traffic generally reflects legitimate user sessions and application activity. Flow duration, packet counts, byte rates, protocol use, and inter-arrival times vary with the application and time of day. Normal traffic is not necessarily low-volume; legitimate events can also create spikes.

ATTACK TRAFFIC

Possible warning signs

DoS/DDoS traffic may show unusually high packet or byte rates, repeated connections, many short flows, unusual timing patterns, or distinctive packet and TCP-flag distributions. No single feature proves an attack; signals must be interpreted together and in context.

AVAILABILITY

Why detection matters

Timely detection can help a security team apply rate limiting, filtering, upstream DDoS protection, traffic scrubbing, or capacity scaling. Detection supports response, but it does not by itself stop an attack or guarantee uptime.

LIMITATIONS

Interpret results carefully

CIC-IDS2017 is a benchmark dataset collected in a controlled environment, not a live production network. Flow labels and feature distributions may contain dataset-specific artifacts. Random train/test splits can overstate generalization when similar traffic appears in both sets. A model score does not guarantee real-world protection.

FUTURE IMPROVEMENTS

Stronger evaluation

  • Use time-based or day-based holdout testing.
  • Compare Random Forest with a simple baseline and anomaly detection.
  • Inspect per-class errors and feature importance.
  • Test on another public dataset and monitor false alarms.
  • Explore how rate limiting, WAF rules, CDN protection, and upstream scrubbing complement detection.
